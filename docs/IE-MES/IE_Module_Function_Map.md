## Document set & workflow

| Document | Audience | Role |
|----------|----------|------|
| **Business Logic Spec** | Developers (and Claude Code when building) | The **rules of record**: unambiguous, numbered, testable. Where documents disagree, the spec wins. |
| **Framework Rationale** | Peter, management, reviewers | *Why* the model works, with worked numbers. The review and buy-in document. |
| **Function Map** (this file) | Planning | **v1 scope** index. Anything not in v1 is removed or listed under *Potential later additions*. |

**Rules**
1. **The spec and rationale are a pair.** They describe the same logic and are never finalised separately.
2. **Workflow per change:** decide → write the rule in the spec → explain and recompute in the rationale → update scope in this map. All three in the same batch, each with a change-log entry.
3. Before editing any document, proposed changes are stated and confirmed first.
4. New versions of the spec and rationale are saved as new files (`_v0.x`); earlier versions are kept as history.

**After the business logic baseline**, in this order: (1) trim this map to v1 scope ✔ (2026-10-18); (2) acceptance test cases; (3) technical design.
- **Acceptance test cases:** the rationale's running example turned into input → expected-output tables, generated by the verification script. Code is correct when it reproduces them.
- **Technical design / Odoo mapping:** how each concept maps onto Odoo objects (work centres, MOs, work orders, attendance, quality). The FLAG-TECH items are its seed.

## Design principles

1. **Layered data flow:** *Master data → Engineered standard → Line design → Execution → Feedback.* Standards change rarely and only through a controlled process. Actuals are captured continuously.
2. **Minutes are the common unit.** Costing, capacity, efficiency and pay are all expressed in standard minutes.
3. **Earned minutes stay pure.** Earned minutes = good pieces × SAM. Pay adjustments (proficiency factor, defect deduction, tier multiplier, ramp-adjusted threshold) live in separate *incentive minutes* or in the *threshold* (Spec §11).
4. **Output over duration.** Efficiency = earned minutes ÷ clock time (attended − approved off-standard). Bundle durations never enter the incentive denominator; they are used for diagnostics and to split time between families for skill evaluation (Spec DEC-02).
5. **Standard vs actual is kept separate.** The gap between them drives improvement work. It is never silently written back into the standard.
6. **Desktop for engineering, mobile for the shop floor.**
7. **Pay-grade rigour.** Every pay-relevant input is traceable and defensible.
8. **IE outputs metrics; payroll pays** (Spec DEC-08).
9. **Calibrate before pay:** shadow mode before pay-relevant parameters go live (Spec DEC-16, §14).

## 1. Work Measurement & Master Data

| # | Function | Description |
|---|----------|-------------|
| 1.1 | **Operation Master / Library** | Reusable operations with the fields the logic needs: **library operation code, name, operation family, machine class, SAM** (with version). *v1 light:* extended technical attributes (attachments, gauge parts, needle, thread, seam type, SPI) are a later addition. |
| 1.2 | **PMTS Data Ingestion** | Imports operation breakdowns, methods, **library operation codes**, SAM and machine classes from **timeSSD**. *v1 light:* file import; automated sync is a later addition. |
| 1.4 | **Difficulty & Complexity Grading** | Grade A/B/C per operation family, set by the grading rubric: critical, position/visibility, precision/handling, machine type (Spec §5.6). Used in skill-tier criteria and allocation rules, **not** as a direct pay multiplier and not in earned minutes. |
| 1.6 | **Operation Family Mapping** *(new)* | Maps each style-specific operation to a generic operation family (family + grade + machine class). Skill is measured at family level, so it carries across styles. Families on automatic/programmable machines are flagged **not skill-evaluated** (Spec DEC-12, §10.1). |

## 2. Operation Bulletin & Standard Control

| # | Function | Description |
|---|----------|-------------|
| 2.1 | **Operation Bulletin (OB)** | Per-style operation sequence with a flow chart (preceding and following operations), machine, attachments, SAM per operation, and total garment SAM per department. |
| 2.2 | **OB / SAM Version Control** | Versioned SAM with effective dates. Production records use the version effective on their completion date (Spec §5.2). |
| 2.3 | **SAM Amendment & Dispute Records** | Amendments only for a spec/method change or a proven standard error. The system records the dispute, evidence, decision and approver, and versions the SAM with its effective date. Verification itself is IE practice outside the system (Spec §5.3–5.4). |

## 3. Pre-Production Costing & Capacity

*Not in v1.* The costing stream (CPM, CM cost, E_plan, order-level load, machine requisition, actual labour cost) is listed under *Potential later additions*. Spec §6 keeps its logic. The **self-funding check (7.9) stays in v1**: it uses payroll actuals and earned minutes only, not costing.

## 4. Line Engineering & Balancing

| # | Function | Description |
|---|----------|-------------|
| 4.1 | **Line Layout / Station Design** | Maps the OB to stations respecting precedence and machine class; combines low-SAM operations and splits high-SAM ones. The resulting station layout is **recorded and versioned per line**; real-time monitoring uses it (Spec §7.2). |
| 4.2 | **Takt & Pitch Time** | **Takt** = available minutes ÷ target (the pace demand requires). **Pitch** = garment SAM ÷ operators (the average workload per operator) (Spec §7.1). |
| 4.3 | **Balance Metrics** | Line balance efficiency, balancing loss %, unused minutes per station, bottleneck identification (Spec §7.3). |
| 4.4 | **Skill-aware Operator Allocation** | Rule: bottleneck and Grade A stations go to U/O-level operators. *v1 light:* a report of qualified operators per station (by skill level); what-if simulation is a later addition (Spec §7.4). |
| 4.5 | **Style Changeover & Learning Curves** *(rewritten)* | Changeover definition; **familiarity score** from library operation codes; ramp classes R0–R3 (IE confirms or overrides); learning curve = plateau × ramp profile; ramp profiles **fitted from the factory's own changeovers** (U/O operators only), with bootstrap profiles until enough data exists. Plateau per line × product type; the product type is an IE field on the product category. One curve family serves targets, costing and the incentive threshold (Spec §7.7). |
| 4.6 | **Daily Target & Headcount** | Daily target = operators present × T × e(d) ÷ garment SAM; headcount needed for a daily target = target × SAM ÷ (T × e). Recalculated for actual headcount (Spec §6.4, §7.5). |

## 5. Shop-Floor Execution (MES Bridge)

| # | Function | Description |
|---|----------|-------------|
| 5.1 | **Bundle = MO & Bundle Ticket Interface** | MOs split by variant → shade lot → bundle size. **One operator per operation per bundle**, credited with the full bundle quantity. Operators never enter quantities. Mid-bundle reassignment is a supervisor-only action with an audit log (Spec §8). |
| 5.2 | **Bundle Scans (Timing)** | Start and finish scans per bundle operation. Durations used for pace, flow, coverage and family time allocation, **never in the incentive denominator** (Spec DEC-02). |
| 5.5 | **Off-Standard Bucket** *(rev.)* | One record shape (operator(s), time, reason, approver), fed by three channels: **work-order pause** with a reason, **manual entry by the line leader** (waiting for work, meetings, setup, line-wide stops), and **repair records**. Approval required; no overlaps; clipped to attendance; audited by approving leader (Spec §3.3, DEC-17). |
| 5.6 | **Defect → Repair → Re-inspection Interface** | Receives defect records (bundle, operation, code, qty, detection point, responsibility) and repair records from the Quality module. Attributes defects to the operator through the production record (Spec §9). |
| 5.7 | **Time Sources & Data Quality** *(new)* | Attendance is the master clock for pay; server timestamps; bundles paused or finished by operators and leaders, with an optional nightly pause job for bundles left open; data-quality exception list cleared before payroll close. Clipping bundle time to attendance not decided `[OPEN-15]` (Spec §3.4, DEC-18). |

## 6. Performance Metrics & Skill Matrix

| # | Function | Description |
|---|----------|-------------|
| 6.1 | **Time Accounting Engine** *(new)* | Splits attended time into approved off-standard and net available minutes (NAM). One model feeding all metrics (Spec §3). |
| 6.2 | **Earned Minutes Engine** | Gross EM = pieces × SAM. Net EM = gross − defect deductions (defective qty × SAM, booked on the detection date) (Spec §2, §9.3). |
| 6.3 | **Efficiency Metric Family** | On-standard (EM_n ÷ NAM), overall (EM_g ÷ A), line, off-standard ratio, plus diagnostic pace and bundle coverage (Spec §4). |
| 6.4 | **Dynamic Skill Matrix** | Per operator × **skill-evaluated** operation family: family efficiency (NAM allocated by bundle time), defect rate, minimum volume, ILUO levels with downgrade grace and dormancy rules (Spec §10.1–10.4). |
| 6.5 | **Operator Tier (Versatility)** | T1–T4 from the number of U/O skill-evaluated families, Grade A coverage and machine classes (automatic machines never count); fixed for the next pay period (Spec §10.5). |
| 6.6 | **Calibration & Shadow Mode** | The full system runs but the incentive isn't paid out; builds skill history and calibration data, then switches on after acceptance checks (Spec §14, `[OPEN-12]`). |
| 6.7 | **Parameter Configuration** *(new)* | All `[P]` parameters editable by their owners and versioned with effective dates (Spec DEC-21, §14.1). |

## 7. Incentive Metrics & Payroll Feeder

| # | Function | Description |
|---|----------|-------------|
| 7.1 | **Individual Incentive Basis & Scope** | Individual incentive on the operator's own output (Spec DEC-01), covering all SAM-measured work by anyone. Roles without SAM output are outside the IE incentive (Spec DEC-14). The line share (hybrid) is a future option `[OPEN-10]`. |
| 7.2 | **Proficiency Factor (Leeway)** | Incentive minutes credit work at levels I/L with a factor (e.g. 1.25 / 1.10) on the first **PF_cap earned minutes** in a family (cumulative across periods, no reset; cap set per grade). Ends at U or at the cap. Not applied to not-skill-evaluated families (Spec §11.2). |
| 7.3 | **Threshold & Excess Minutes** | Threshold = Σ daily θ_day × NAM, where θ_day follows the ramp profile on style ramp-up days (weighted by the operator's share of ramping-style work, with a floor). Excess = max(0, IM − threshold), aggregated per pay period (default monthly, `[OPEN-03]`) (Spec §11.3). |
| 7.4 | **Tier Multiplier** | Payable units = excess × M_tier (Spec §11.4). |
| 7.5 | **Defect Deduction** | Direct deduction from the responsible operator's earned and incentive minutes; repair is neutral off-standard time for the repairer (Spec §9.3–9.4). |
| 7.6 | **Off-standard Protection** | Approved off-standard minutes (incl. waiting for work, repair) are excluded from NAM. |
| 7.7 | **Special Skill Allowance Metrics** | Skill level and tier metrics reported so payroll can grant an allowance to highly skilled operators. The allowance decision and amount belong to payroll/HR (Spec DEC-06). Also covers rare floater cases (Spec DEC-15). |
| 7.8 | **Payroll Feeder** | Per operator per period: attended minutes, off-standard minutes by code, EM, deductions, IM, efficiencies, excess and payable units (one total; no time-category split in v1), tier, eligibility flags. Payroll applies rates, statutory premiums and allowances (Spec §12). |
| 7.9 | **Self-funding Check** | Labour cost per earned minute vs efficiency, to keep the scheme self-financing (Spec §11.8). |

## 8. Analytics & Continuous Improvement

| # | Function | Description |
|---|----------|-------------|
| 8.1 | **Planned vs Actual SAM** | Pace per operation vs SAM; feeds the dispute and amendment process (2.3). |
| 8.2 | **Line Efficiency Progression** | Daily line efficiency vs the planned learning curve, per style/MO. |
| 8.3 | **Lost-Time Analysis** | Off-standard minutes by code, line and station. Waiting for work is the balancing KPI; breakdowns and material waits point to supply and maintenance; changeover setup shows changeover cost. |
| 8.4 | **Quality Analytics** | Defects by family, operator, code and detection point; repair minutes. |
| 8.6 | **Incentive Health** | E_inc distribution, share of operators above threshold, self-funding check. |
| 8.8 | **Changeover Analysis** *(new)* | Observed vs fitted ramp profiles per changeover; ramp-class mix and IE overrides per line; profile refit status (Spec §13). |
| 8.9 | **Off-Standard Audit** *(new)* | Off-standard minutes by code, channel and approving leader; data-quality exception volumes (Spec §13.1). |

## 9. Real-Time Monitoring (v1: RT-1 to RT-7)

Same definitions as the period metrics, computed continuously over a rolling window; diagnostic only (Spec DEC-19, DEC-20, §13.2).

| # | Function | Description |
|---|----------|-------------|
| 9.1 | **Hourly Production Board** (RT-1) | Per line: output vs hourly target (current hour and cumulative), rolling efficiency, headcount present, off-standard minutes today. Hourly target = operators present × 60 × e(d) ÷ garment SAM. Includes hourly output per operator (formerly 5.3) and a **daily management report** (formerly 8.7). |
| 9.2 | **Exception Alerts** (RT-2) | Line below target, off-standard pending approval, bundle open too long, station starved, buffer above the WIP cap (`[P]` thresholds). |
| 9.3 | **Breakdown Call → Maintenance Request** (RT-3) | A work-order pause with reason "breakdown" notifies the mechanic and opens a CMMS maintenance request. |
| 9.4 | **Operator Figures Feed** (RT-4) | Today's provisional operator figures supplied to the separate MES interface. Display is outside IE scope. |
| 9.5 | **Station WIP Flags** (RT-5) | Input buffer per station, WIP caps, starved and overloaded flags; the line leader controls bundle release (formerly 5.4; Spec §7.6). Uses the recorded station layout (4.1). |
| 9.6 | **Live Bottleneck** (RT-6) | Lowest throughput ratio (completions vs planned station output) among stations not starved. |
| 9.7 | **Station Pace** (RT-7) | Live pace vs SAM per station (diagnostic). |
